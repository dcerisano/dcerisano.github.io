# RGBify Projector firmware (companion)

- Repo: `~/git/rgbify-projector` (`git@bitbucket.org:standard3d/rgbify-projector.git`, branch `master`).
- ESP32 Arduino sketch in `rgbify-projector-esp32/`; 8x8 WS2812B matrix on pin 27, piezo buzzer (toneAC fork), FastLED 3.9.0 + LEDMatrix + LEDText.
- arduino-cli, ESP32 core 2.0.17. `NUM_HANDLES` (19) passed to `createService` (default 15 too low for 6 characteristics). NOTE: default partition build is at 101% (pre-existing overflow, compiles fine with `PartitionScheme=huge_app`).
- Power limiting: `FastLED.setMaxPowerInVoltsAndMilliamps(5, MILLI_AMPS)` (1600mA) + `setBrightness(255)` in setup(). Solid color is gamma-corrected like other modes.
- Device Information Service (`0x180A`) exposes firmware version (`FIRMWARE_VERSION` macro in `ble.h`, currently "0.1.5"). No Service Changed characteristic (deliberate: rare GATT changes, manual re-pair is fine).
- Live-mirror broadcast: `loop()` calls `broadcastProjectorFrame()` (ble.h) every tick after `FastLED.delay` — packs `leds[]` into a SEPARATE `mirrorFrame[256]` buffer (same reflection mapping as `updateProjector()`, alpha=255), change-detects (static `lastBroadcast[256]`), and `notifyAll()`s the projector characteristic so every client (including the writer) mirrors the physical display. `notifyAll()` is like `notifyOthers()` but without the excludeConnId skip. CRITICAL: never write the gamma'd leds back into `projector[]` — it's the ambience input buffer; doing so made `updateProjector()` re-gamma every tick and fade ambience to black.
- Implements the BLE service the web app drives — see `mem:ble_protocol`. Full protocol/build docs in its README.
